# 2026-09-13 — Session 85r — LEG-091 implemented (step resolver: local | remote | error, pre-deposit gate)

## Scope

The maintainer confirmed the local-first federation framing (work travels,
lifecycle stays local) and asked to continue. This turn: refresh the stale
LEG-091 DRAFT contract to the modern triangle and implement the author-side
step resolver red-first as a *pure decision* module.

## Work done (per issue)

- **LEG-091 — contract refreshed** `docs/CONTRACTS/LEG-091-step-resolver.md`:
  the DRAFT referenced the LEG-015 in-memory `Federation`/`_NODES`. Modern
  mapping: local capacity = `pattern_catalog.served()` (the same roster LEG-090
  exposes); peer catalogs = LEG-090 `GET /catalog` responses fetched by the
  author-side client (LEG-092); the resolver is a **pure decision** — no
  beaver, no HTTP, no deposits. Records the maintainer's local-first framing
  explicitly (federation transports work, never lifecycle: no federated
  lifecycle endpoint exists, and control messages are signed per-boot so a peer
  could not mint them anyway, LEG-082).
- **LEG-091 — implementation** `src/legio/federation.py` (new): `Local` /
  `Remote` frozen dataclasses; `StepResolver(local_capacity, peer_catalogs)` —
  `resolve(agent)` order: local capacity → first offering peer in order decides
  (matching `schema_version` → `Remote`; mismatch → visible
  `InterfaceMismatchError`, never a silent skip); peer without the agent
  skipped; nothing offered → `UnresolvableAgentError` (LEG-016 taxonomy, rooted
  in `LegioError`). The resolver is read-only: raising *is* the pre-deposit
  gate, so nothing unresolvable is ever queued (ARCH §9).
- **LEG-091 — tests** `tests/test_leg091_step_resolver.py` (9, red-first —
  module absent → collection error — then green): served → Local; capacity
  tracks invalidation; peer-offered matching → Remote; schema mismatch fails
  loudly; mismatch not skipped to a later match; peer without the agent skipped
  (later peer decides); first offering peer wins; unresolvable → error; purity
  pin (resolve never deposits or mutates capacity).

## Logging added

## Decisions taken

- The first offering peer in the configured order wins (deterministic,
  order = the author's `federation.peers` list later).

# 2026-09-13 — Session 85s — LEG-092 implemented (work-item over HTTP, remote deposit, idempotent)

## Scope

The maintainer confirmed the local-first framing (work travels, lifecycle stays
local) and asked to continue. This turn: refresh the stale LEG-092 DRAFT
contract to the modern triangle and implement the acceptor's work-item intake
red-first. The author has already resolved the step (LEG-091); the acceptor
validates the interface and deposits a genuine business task keyed by the
author's task id.

## Work done (per issue)

- **LEG-092 — contract refreshed** `docs/CONTRACTS/LEG-092-work-item-http.md`:
  the DRAFT referenced the LEG-015 in-memory `Federation._queues`. Modern
  mapping: the acceptor's deposit **is** its own business task path —
  `Runtime.submit_work_item` mirrors the business submit, but the task id is
  the author's and the owner is the author's node id (task_id origin). No
  separate acceptor queue: the root `ExecutionRequestMessage` lands on the
  acceptor's class queue under the author's id, so the result goes to the
  author's result queue and a retried delivery is idempotent (LEG-093
  prerequisite). Records the validation order (token → 401; no pattern catalog
  → 503 `no_capacity`; not served → 404 `unknown_agent`; schema mismatch → 409
  `interface_mismatch`; gate → 409 `class_disabled`; deposit) and the
  local-first pin (surface never accepts a lifecycle verb).
- **LEG-092 — implementation** `src/legio/runtime/__init__.py` gains
  `WorkItemReceipt {id, deposited, deduplicated}` and
  `Runtime.submit_work_item(author, route, payload, *, task_id)` — the same
  entry gate, root flow token and `seed` fact as `submit`, but the id is
  author-minted and a duplicate `task_id` (Manager's visible "already exists"
  rejection, rule 9) is translated into a **deduplicated receipt**, never a
  second execution. `src/legio/api.py` mounts `POST /work-items/{agent}`
  alongside `GET /catalog` when a federation token is configured: request model
  forbids extra fields (a lifecycle verb is refused, not dropped — federation
  transports work only); `task_id` format validated first (422), author
  derived from the task_id origin, route derived from the served spec.
- **LEG-092 — tests** `tests/test_leg092_work_item.py` (8, red-first — endpoint
  absent → 404 — then green): valid work item deposits into the acceptor's
  queue as a genuine Manager seed task keyed by the author's id; the same id
  delivered again → `deduplicated` receipt and exactly one task record; no
  token / wrong token → 401; unconfigured → 404; unknown agent → 404; schema
  mismatch → 409 (nothing deposited); a lifecycle verb in the body is refused
  (extra-field model); a fully booted node with `LEGIO_FEDERATION_TOKEN`
  accepts a work item over `BootedNode.app`.

## Logging added

- `legio.runtime` `submit_work_item` (with the implementation, rule 11): WARNING

  `runtime work_item dedup task=… class=… reason=…` (dedup is a decision,
  never silent).
- `legio.api` work-item endpoint: WARNING on unauthorized / unknown agent /
  interface mismatch / invalid id (denials visible), ERROR `- no capacity`
  (federated node with no pattern catalog — rule 9), INFO on deposit.

## Decisions taken

- The acceptor's work-item deposit **is a genuine business task** (the same
  seed fact as a local submit), never a separate "federation queue": one
  execution path, one ownership model, one result flow (LEG-093 polls the
  author's result queue).
- Author-minted task ids make hand-offs **idempotent at the acceptor**: a
  duplicate is refused by the Manager and surfaced as a `deduplicated` receipt
  (write-before-ack, at-least-once) — never re-executed.
- The request model is `extra="forbid"`: lifecycle verbs and any out-of-contract
  field are refused loudly (rule 9), pinning "federation transports work, never
  lifecycle" (maintainer session 85q).
- Interface check stays server-side too (409 `interface_mismatch`) even though
  LEG-091 already validates author-side: the acceptor double-checks what it
  executes (`schema_version == SCHEMA_VERSION`).
