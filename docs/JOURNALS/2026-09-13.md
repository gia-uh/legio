# 2026-09-13 — Session 85t — LEG-093 implemented (author outbox: poll + destructive ack, write-before-ack)

## Scope

The maintainer asked to continue after LEG-092. This turn: refresh the stale
LEG-093 DRAFT contract to the modern triangle and implement the author-side
result readback red-first: the outbox verbs over the acceptor's REST surface.

## Work done (per issue)

- **LEG-093 — contract refreshed** `docs/CONTRACTS/LEG-093-outbox-polling.md`:
  the DRAFT referenced the LEG-015 in-memory `Outbox` (author-side buffer) and
  LEG-020 queue dedup. Modern mapping: **the acceptor's outbox is the task's
  result queue** (`result_queue_key(task_id)`) — the exact queue the agent
  flow already writes the `ExecutionResultMessage` onto at the end of level 1
  (`_route_outcome` → `_deposit_result`), *during* execution. That makes
  write-before-ack **structural**: the write happens at execution time, before
  any ack can occur — no helper or explicit ordering. Idempotency needs no
  queue dedup: the Manager's existing "duplicate task_id" rejection (rule 9)
  refuses the second deposit before a second seed is ever minted (LEG-092).
  Records the local-first pin (the outbox surface never accepts an operator
  verb) and the symmetric-trust ownership model (a peer only polls its own
  author-minted task ids).
- **LEG-093 — implementation** `src/legio/runtime/__init__.py` gains
  `Runtime.read_outbox(task_id)` (non-destructive peek of the result queue,
  returns the `ExecutionResultMessage` payload or `None` — non-blocking,
  rule 8) and `Runtime.ack_outbox(task_id)` (destructive `get`; already-empty
  → `False`, idempotent, never an error). `src/legio/api.py` mounts `GET
  /outbox/{task_id}` → `{id, ready, result}` and `DELETE /outbox/{task_id}` →
  `{id, acked}` under the federation token, sharing one L1 + task-id guard
  (`_guard_outbox`) → 401 no/wrong token, 422 invalid task id.
- **LEG-093 — tests** `tests/test_leg093_outbox.py` (9, red-first — endpoint
  absent → 404 — then green): poll on an empty outbox → `ready: false`; poll
  after the result is deposited → `ready: true` with payload; ack consumes and
  re-read is empty; ack on empty is a no-op (`acked: false`); **write-before-
  ack pin** (the result is readable before any ack, the ack never triggers the
  write); **idempotency at the queue-message level** (same work item POSTed
  twice → one seed dispatched → exactly one `ExecutionRequestMessage` on the
  class queue); 401 no/wrong token; 404 unconfigured; 422 invalid task id.

## Decisions taken

- **The outbox is not a new surface**: it is the per-task result queue, already
  written by the flow — `read_outbox`/`ack_outbox` are seams, the endpoints a
  thin read/consume shell. No new beaver scope (footprint, rule 13).
