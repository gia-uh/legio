## 4. What exists NOW (do not re-build)

### 4.1 The decoupled triangle (committed, green)
- **Manager** (`src/legio/manager/`): generic task env — scopes `tasks`,
  `pending_tasks`, `control`; `register(name, callable)` (async fn **or async
  generator**); `submit_task` (`<node_id>:<uuid>` task_ids, validated); one-pass
  `run()`; parked generators (`_drive_parked`) occupy the dispatch executor for
  their whole lifetime; `_last_yields` carries generator results.
- **Registry** (`src/legio/registry/`): posterior mirror — scopes `catalog`,
  `instances`, `yaml_cache`; effective state = stored enabled AND ≥1 recorded
  instance; never initiates, chooses never.
- **Runtime** (`src/legio/runtime/`): the orchestrator — **owns exactly two
  scopes: `gates` + the `node_ops` intake**; lifecycle verbs as
  "action → Manager fact → (bounded Manager-read confirm, §5.8) → Registry
  record"; business `submit`/`status` on the Runtime (seed task); gate check at
  deposit; boot via `create_from_catalog` (topological, leaves first).
- **`legio.flow.control`**: `ControlMessage` + HMAC `sign`/`verify`; the agent
  holds only `verify`; per-boot in-process node key.

### 4.2 LEG-088 intake surface (the CLI's seam)
- `Runtime.deposit_node_op(verb, class_name, instance_id=None) -> str` — the
  Runtime decides intent validity (known verb, live class, live instance for
  instance verbs; instance verbs require an instance, class verbs forbid one);
  rejects are visible `RecoverableError`s, never minted. Deposit **only queues**
  the typed `NodeOp` and schedules one `NODE_OP` Manager-fact drain; it never
  touches an agent queue and mints nothing.
- The `NODE_OP` drain pops **one** intent per dispatch and self-re-submits
  while the intake is non-empty (a `count()` field read — the "scheduling
  field", never a sleep); tampered intents on the queue fail the drain visibly
  (`failed` record naming the raw payload) and never mint.
- Exports on the runtime package: `NODE_OP_TASK`, `NODE_OPS_SCOPE`,
  `CLASS_OP_VERBS`, `INSTANCE_OP_VERBS`, `NODE_OP_VERBS`, `NodeOp`,
  `deposit_node_op`.
- Tests proved (red-first, `tests/test_leg088_node_ops.py`, 8 green): intents
  reach a live instance as **signed** messages on the one-shot vehicle;
  mounted disable→enable→destroy are honored **between dispatches** by the real
  standing loop (seq ≥ 2, record `running` throughout, destroy → terminal);
  the footprint pin: dicts = Manager/Registry scopes + `gates` only, queues =
  `{pending_tasks, node_ops}` only.

### 4.3 Operational gotchas (learned 85m-85o — don't rediscover)
- **Executor occupancy**: a `NODE_OP` (or lifecycle-fact) drain occupies its
  dispatcher while it awaits a Manager-read confirm, so the §6.1 doctrine applies:
  the pool needs **multiple executors** (`_start_executor(runtime, pumps=3)`
  started **before** `create_class`). One pump is NOT enough.
- **beaver** queue: `put(data, priority=...)` requires the `priority=` kwarg;
  `get(block=False)` is destructive and raises `IndexError` on empty; `count()`
  and `peek()` are the non-destructive reads. Scopes are enumerable via
  `__beaver_dicts__.dict_name` / `__beaver_priority_queues__.queue_name`
  (used by the footprint-pin tests).
- **One-shot born-enabled**: freshly spawned instances are born ENABLED, so
  `enable_instance` on the one-shot vehicle is a no-op ("already enabled"
  WARNING, mints nothing) — mint tests use `disable_instance`.
- **Pickles/gotchas in tests**: predicates that merely *compare* a coroutine
  (`lambda: _instance_state(...) == X`) yield "coroutine never awaited" warnings
  and never-passes — use async predicate helpers (`_state_is`, `_status_is`)
  with a `_wait_until` that awaits awaitables (`inspect.isawaitable`). On `now`/
  mounted destroy, the bring-up record flips to SUCCESS at agent-loop exit
  **before** Registry `remove_instance` runs — wait on **both** the status and
  the registry state.
- `control` Manager scope keys are task_ids (task-control); `node_ops` is the
  intake; the **names never collide** and a runtime test pins that.
