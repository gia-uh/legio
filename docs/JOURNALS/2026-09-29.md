## Work done

### Diagnosis (evidence-based, no change made while diagnosing)

- Anonymous checkout comparison `git show HEAD:<file>` vs working tree showed the
  assistant had (all reverted this turn):
  - `patterns/linguistic/article_outline.yaml`: recursive `children` → flat
    `array of string` (the assistant wrongly blamed a "recursive schema compiles
    to an invalid `response_format`" compiler bug).
  - every `patterns/composite/*.yaml` and `text_*.yaml`: `required` relaxed to
    `[transcript]` / `[]`, which **masks a missing branch instead of reporting
    it** (AGENTS.md rule 9).
  - `patterns/linguistic/*.yaml`: `timeout` lowered 300/600 → 60.
- Root cause of the *original* `blog_post_draft` failure in the assistant's run:
  the `timeout: 60` made `article_outline` time out on slow LM Studio; under
  0.1.4's filtering `build_output_as` that missing branch became a hard
  `required` failure, cascading up. The assistant then "fixed" the symptom by
  editing schemas and **changed legio** (0.1.5), instead of not lowering the
  timeout.
- Version split found: local invox venv resolved **legio 0.1.4**
  (`uv tree` / `uv pip show`; `uv.lock` pinned 0.1.4; `pyproject.toml`
  `legio>=0.1.4,<0.2`), the VPS used 0.1.5. The local "decoding error" runs were
  therefore on 0.1.4 with the assistant's mangled tree.

### Reverts

- `invox`: `git checkout HEAD -- patterns/` — recursive `article_outline`
  restored; every composite's original `required` restored; `timeout` back to
  300/600. Working tree clean vs HEAD.
- `legio`: `git checkout v0.1.4 -- src/legio/agents/composite_agent.py` — the
  `build_output_as` implementation (including `_declared_output_properties`) is
  byte-identical to v0.1.4 (`git diff v0.1.4` empty for that file). The 0.1.5
  change (merge without filtering) is removed.

### Local end-to-end verification (LM Studio `gemma-4-e4b-it`, legio 0.1.4)

- Restarted STT (Docker, refreshed), cleared `invox/data/invox.db*`, started
  invox on `:8000` pointing at `http://localhost:1234/v1`.
- Ran the 10 pipelines with `fixtures/jfk.flac`:
  - **9/10 OK**: `transcribe, idea, generic, to_do, reminder,
    email_simple_draft, interview, meeting, project_roadmap`.
  - `blog_post_draft` failed with `problems=analysis:missing`.
- Logs show the true failure: **`write_draft` → `BadRequestError: 400 -
  {'error': 'terminated'}`**. `article_outline` **succeeded** (recursive schema,
  ~76 s) in the same run — so the recursion is *not* the problem. LM Studio's own
  log confirms `[ERROR][gemma-4-e4b-it] Error: Channel Error … TypeError:
  terminated`, i.e. the local engine aborted a concurrent request. `write_draft`
  fires in parallel with the four `text_blog_post_draft` leaves; LM Studio serves
  one generation at a time and terminates the extra one. This is a **local-model
  concurrency limitation**, not invox, not legio, not the schema.

## Decisions taken

- **The original invox schemas are correct and are restored.** The recursive
  `article_outline` works; the `required` lists are the honest contract (a failed
  branch is a visible failure, not a masked gap). The maintainer's statement
  ("todo funcionaba en 0.1.4; tú introdujiste los errores") is confirmed by the
  evidence above.
- **The 0.1.5 `build_output_as` change is withdrawn**: legio's `composite_agent`
  returns to the v0.1.4 implementation. 0.1.5 remains published on PyPI, so a
  follow-up release (e.g. **0.1.6**) is required to ship the v0.1.4 behavior
  again — pending maintainer decision (see open points).
- No consumer/domain content added to legio (rule 7 respected); the revert is
  pure engine behavior.
