### LEG-121 — linguistic steps as `system` + `user` (implemented, released)

Final design (maintainer-approved):

- A linguistic step is a **two-turn chat**: `system` (the role) + `user` (the
  task + data).
- The `system` turn is, in precedence order: the pattern's `system_prompt`
  (a **template**, resolved against the payload, variable-checked like `prompt`);
  else the **node config's general** `system_prompt` (new top-level field,
  **static** text); else empty.
- The `prompt` (the `user` turn) is **never** copied into the `system` turn.
- Schema 1: optional `system_prompt` for `kind: linguistic`.
- Config (`LegioConfig`): top-level optional `system_prompt`.
- Files: `src/legio/agents/linguistic_agent.py`, `patterns/schema1.py`,
  `patterns/loader.py`, `materializer.py`, `config.py`.
- An earlier `instructions`/`input_text` (two-field split) and a "duplicate the
  prompt into both turns" variant were **rejected** during the session as an
  incomplete model of chat; the role/task split into `system_prompt`/`prompt` is
  the agreed model.

## Decisions taken

- A linguistic step is modelled as `system` + `user`; the role is declarable
  (`system_prompt`), the task stays in `prompt`. The general default lives in
  the node config (static); the pattern override may template.
- LEG-121 named in PLAN; spec approved by maintainer direction this session.
