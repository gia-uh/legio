## Decisions taken
- **Fetch-before-load**: `peer_steps` must be derived before `load_pattern_dirs` so peer-offered branch steps validate at load time (LEG-094 §B/D). Stored the map on `Runtime._peer_steps` so `create_class` can filter dependencies without changing every call site.
- **Local-only dependencies**: `Runtime.create_class` filters via `peer_steps` (explicit or stored) — peer steps are not local dependencies (LEG-094 §C). Without peer context, keep all branch steps as dependencies (preserves `missing_dependency_born_disabled` semantics).
- **Composite pending gather deadlock**: the standing loop's blocking `get(block=True)` on the class inbox starved the gather queue. When `has_pending()` is true, the loop now yields cooperatively instead of dead-blocking, so the next tick re-polls gather. This is the minimal fix that keeps the manager's `run` pumps as the only scheduler (rule 8, polling only).
- **Test pump order**: `create_class`'s `bring_up` observable state needs `manager.run()` pumps alive (bounded `drain_timeout` poll). Moved pumps before `create_class` in the 3-node example (the test's original order deadlocked the bring-up on a single pump).

## Known issues / open points
- `Runtime.create_class`'s peer filter still approximates "local" as "not in effective peer_steps". If a composite references a truly unknown pattern that is also not a peer, it will be incorrectly treated as peer when a peer map is present. A future refinement could pass the local catalog's served set explicitly, but the current heuristic is exact for the directed example and preserves single-node tests.
- `test_roster_wire_carries_entry_input_as` now boots `node-b` with two peers (A and C) to satisfy `brief`'s `spot` peer step — the minimal fix for the wire test; the original single-peer setup was inconsistent with `brief`'s branches.
