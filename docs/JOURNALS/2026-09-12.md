# 2026-09-12 — Session 82 — Stage 1 of the audit-fix plan: gate deposit handshake, destroy-instance terminal confirmation, minted task_id validation

## Scope

The maintainer approved a staged plan to fix the Session-81 code-vs-design
audit deviations (§1: `docs/JOURNALS/2026-09-07-HANDOFF.md`). This turn executed
**Stage 1** (logic bugs, no dependencies): finding #7 (destroy_instance
terminal predicate), #8 (Runtime-minted `task_id` not validated) and #1
(§12.5 deposit-time gate handshake + error-result exemption). Work tree stays
uncommitted (rule 3 — only the journal commits); Stage 1 awaits maintainer
approval before Stage 2 (configurability).

## Work done (per issue)

- **Finding #1 — deposit-time gate handshake (§12.5)**: the gate was only checked
  at `Runtime.submit` (entry); the audit flagged that the §12.5.5 **error-result
  exemption is missing** in the flow deposit paths. Implemented the handshake:
  - `src/legio/agents/base.py` — agent reads `db.dict("gates")` (read-only handle,
    written only by the Runtime, §12.5.2); new `_class_gate_open(class_name)`;
    `_route_outcome` advance now **blocks** a non-error deposit into a disabled
    class (nothing enters a non-enabled class, §12.5.1) and surfaces it as a
    visible `error` result on the level's `end_of_level_queue` (§12.5.5); an
    **error-result deposit is exempt** and always proceeds (§12.5.5). End-of-level
    closes factored into `_deposit_result` (result/gather queues are never classes
    — no gate applies). Module docstring updated.
  - `src/legio/agents/composite_agent.py` — `_fan_out` per branch: a disabled
    first class blocks the branch deposit; the branch's join slot records a
    visible `error` result (rule 9) so fan-in completes and the composite
    surfaces the failure — never a silent drop, never a corrupted join. Module
    docstring updated.
  - Gate semantics: **closed = row present with `{state: disabled}`**; a missing
    row is open (consistent with the existing submit check and the audit's own
    compliance finding). Note: AGENT_LIFECYCLE §12.5.3's "blocked at the missing
    gate" after destroy remains a doc-level tension with "row absent = open"
    (§12.5.2/LEG-085) — deliberately out of scope for this finding; flagged for
    the maintainer.
- **Finding #7 — destroy_instance terminal confirmation**: the predicate accepted
  any `FAILED`. Tightened to the §5.7 design fact: a replayed cancel on a
  completed record is a terminal no-op (SUCCESS confirmed) OR a still-pending
  cancel lands `failed(cancelled)` (FAILED confirmed only when
  `error == "cancelled"`). A bring-up that FAILED for any *other* reason no
  longer passes as "confirmed" — destroy raises a visible `RecoverableError`
  (rule 9). A re-verified deviation: the audit's claim "accepting SUCCESS is
  wrong" was a misreading (the contract itself accepts SUCCESS as the replayed-
  cancel no-op); the tightening now also rejects non-cancel FAILED, which is
  the genuine hardening.
- **Finding #8 — Runtime-minted task_id validation**: `Runtime.submit` now calls
  `validate_task_id(task_id)` after minting (import added). The minted
  `<valid-node>:<uuid4>` always satisfies the schema, so this is a defensive
  consistency fix pinned by the existing submit test — no observable red could be
  crafted (the invariant already held).
- **Tests written red first** (4 new, all red before implementation where a red
  was observable):
  - `tests/test_leg023_agentbase.py` — blocked advance → not delivered to the
    closed class + visible error on `end_of_level_queue`; error-result deposit
    exempt (advances through the closed gate).
  - `tests/test_leg041_multi_branch_composite.py` — closed branch not fanned
    out; its join slot records a visible error; the open branch still fans out.
  - `tests/test_leg085_runtime.py` — destroy confirms `failed(cancelled)` and
    refuses a non-cancel `FAILED` (RecoverableError, instance/map untouched).

# 2026-09-12 — Session 83 — Teardown of the legacy mini-manager surface (finding #2, resolving #3/#4): api.py/materializer/tests re-targeted to the Runtime

## Scope

The maintainer approved the audit-fix teardown stage. This turn removed the
remaining legacy, domain-coupled surface from `legio.manager` — the module-level
`submit`/`status` and their global scaffolding — and re-targeted the API, the
materializer and every affected test to the `Runtime` (LEG-085). This closes
audit finding #2 (critical), and removes findings #3 `_DEFAULT_NODE_ID="local"`
and #4 (module globals) by eliminating the globals instead of re-homing them.
Work tree stays uncommitted (rule 3 — only the journal commits); the teardown
awaits maintainer approval.

## Work done (per issue)

- **Finding #2 — legacy `submit`/`status` teardown** (`src/legio/manager/__init__.py`):
  removed `submit`, `status`, `connect_manager`, `reset_manager`, `close_manager`,
  `db`, `task_registry`, `agent_queue`, `_new_task_id`, `_current`, the module
  globals (`_DEFAULT_DB_PATH`, `_DEFAULT_NODE_ID="local"`, `_db`, `_db_path`,
  `_node_id`) and the `_TASKS_SCOPE` module global. Imports narrowed to the
  domain-free set (`validate_node_id`, `validate_task_id`, `uuid`, `AsyncBeaverDB`,
  pydantic, stdlib). Module + `Manager` docstrings rewritten (the generic engine,
  domain-free, hosts only `Manager`/`TaskStatus`/`TaskRecord`/`AsyncBeaverDB`
  re-export; `__all__` = `["AsyncBeaverDB", "Manager", "TaskRecord", "TaskStatus"]`).
- **Business view models re-homed**: `TaskState` and `TaskEntry` (they carry a
  `FlowToken` — a business concept, rule 7 keeps the manager domain-free) moved to
  `src/legio/runtime/__init__.py`, defined there with pydantic + Enum.
- **`api.py` re-targeted**: `create_app(runtime: Runtime, clients=None,
  pattern_catalog=None)`. `POST /submit` → `runtime.submit(client_id, route,
  body.payload)`; `GET /status/{task_id}` → `runtime.status(task_id,
  resolved_client)` (PermissionError→403 `access_denied`, KeyError→404
  `unknown_task`, unchanged). `Runtime.status` signature relaxed to
  `client_id: str | None`: an anonymous open-mode requester is denied exactly
  like a foreign client (403), mirroring the legacy behavior; the `TaskEntry`
  owner comes from the Manager record (cast), not the requester.
- **`materializer.py` re-targeted**: `boot_node` connects `AsyncBeaverDB` directly
  (no `connect_manager`) and builds `Runtime(database, node_id=cfg.node.id)`;
  `NodeRuntime` gained a `runtime: Runtime` field; `NodeRuntime.app` →
  `create_app(runtime=self.runtime, clients=self.client_store,
  pattern_catalog=self.catalog)`.
- **`tests/conftest.py`**: `beaver_db` fixture connects/closes an `AsyncBeaverDB`
  directly (no `manager.reset_manager/db/close_manager`); added a shared `runtime`
  fixture (`Runtime(beaver_db, node_id="toplevel@test")`, `NODE_ID` constant).
- **Tests re-pointed** (with the semantic pump fix, see Decisions): `test_leg014`
  (submit/status/TaskState via Runtime), `test_leg025` (client fixture builds app
  over the runtime; `"local:"` pin → `"toplevel@test:"`), `test_leg027` (app fixture
  passes runtime; pin updated), `test_flow_integration_decoupled` (Runtime +
  pump), `test_leg026_e2e` + `test_leg032` + `test_leg043` (both) + `test_leg044`
  (runtime passed to `create_app`), `test_leg081_boot`
  (`boot@test:` pin preserved via the node config; `test_boot_full_flow_over_rest`
  pumps `runtime.runtime.manager.run()`).
- **Docs updated** (per DoD, API changed): LEG-085 (ownership decision → teardown
  record; DoD and open item 1 resolved), LEG-083 (out-of-scope wording), LEG-081
  (boot sequence + `NodeRuntime.runtime` + `create_app` signature), LEG-025
  (title + endpoint delegation), ARCHITECTURE §2 (no `await manager.db()`).

## Decisions taken

- **The node pump dispatches the seed** (semantic change vs legacy): the legacy
  `manager.submit` deposited the root message synchronously; `Runtime.submit`
  mints a Manager `seed` task whose deposit lands only when the node pump runs
  `manager.run()` (ARCHITECTURE §7.1, the decoupled model). REST/flow tests now
  pump deterministically once after submit (`await runtime.manager.run()`) —
  the seed is the only pending task, so a single pass dispatches it; no
  background executor needed in these tests.
- `TaskState`/`TaskEntry` live in `legio.runtime` (the business public face), not
  in `legio.manager` (rules 7/10): this resolves the Session-82 relocation
  question.
- `Runtime.status` accepts `None` requester and denies it (owner-scope), so the
  open API mode keeps its 403 for anonymous status reads; `api.py` needs no
  special-casing.
- `test_leg083`/`test_leg085` (generic Manager surface, `submit_task`/`status`/
  `TaskStatus`) are untouched — the Manager itself is unchanged.

## Logging added
