# 2026-09-14 — Session 86c — The leg087 intermittent failure: transient RUNNING race, fixed in the Manager

## Scope
The maintainer rejected the 86b journal's "known flakiness" dismissal of the
single `test_real_bring_up_fails_visibly_when_agent_not_mounted` failure —
rightly: a sometimes-failing test hides a real race. This turn diagnoses it,
reproduces it deterministically, and fixes the root cause (a production bug,
not a test bug).

## Diagnosis (root cause, verified)
- The Manager's `_dispatch` marked **every** task RUNNING *before* driving its
  callable. For parked async generators that makes RUNNING observable during a
  window (RUNNING-write → first drive → FAILED-write) in which the vehicle was
  never alive.
- The Runtime's bring-up confirm (`_await_observable_state`, ok =
  RUNNING|SUCCESS) samples that window: if it reads between the two writes,
  `create_class` on an **unmounted** class falsely succeeds (phantom instance
  recorded, gate opened) and the test fails with DID-NOT-RAISE instead of the
  expected "no standing agent mounted".
- Narrow window (a few beaver awaits), hit only when the pump is desuspended
  mid-dispatch under full-suite load — hence 1 failure in ~4 full runs, green
  standalone. A first naive RED attempt (concurrent sampler, no widening)
  passed on buggy code, confirming beaver awaits rarely suspend in a quiet
  loop; the window was then widened deterministically (test-only delay on the
  RUNNING persist), which fails on buggy code every time and passes on fixed
  code structurally.

## Work done (per issue)
- **LEG-083 (Manager)**: `_dispatch` no longer pre-marks async generators —
  the generator is created parked in-process and `_drive_parked` writes
  RUNNING (+ started_at) only after the first yield lands. RUNNING means
  *parked*, never a transient; a stillborn generator goes PENDING → FAILED
  with no observable RUNNING. Plain callables unchanged. Blast radius checked:
  the only RUNNING-accepting waiter is the bring-up confirm; the destroy path
  waits terminal SUCCESS; pause-before-start still resumes identically
  (record PENDING until parked).
- **Tests**: `tests/test_leg083_manager.py` gains `test_stillborn_generator_never_observes_running` (deterministic RED on old code, GREEN on fixed) and `test_parked_generator_observes_running_while_parked` (steady state preserved).
- **Contracts amended**: LEG-083 dispatch algorithm (RUNNING-means-parked +
  stillborn rule); AGENT_LIFECYCLE §5.2 bring-up paragraph (same rule, 86c).

## Logging added
- None needed: the existing `manager running task=…` INFO now fires at park
  time (same event, truer moment); `manager failed` exception logs already
  cover the stillborn path.

## Tests run
- RED: stillborn test fails on old code (`RUNNING in seen`); GREEN after fix.
- Full suite **390 passed ×2** (388 + 2 new); the 4 most timing-sensitive
  files (083/085/087/088) green across 6 consecutive runs; `ruff` clean
  (2 UP043 autofixes); `pyright` 0/0/0.

## Decisions taken
- **Fix production, not the test**: accepting transient RUNNING as "vehicle
  up" could record phantom instances and open gates for agents that never
  live — the test was correctly pinning the contract, the Manager was
  violating it.
- RUNNING→SUCCESS early-accept stays benign (a parked-then-completing vehicle
  was alive); only RUNNING→FAILED without a park was the lie, now structural.
