# 2026-09-05 — Session 38 — `build_output_as` seam everywhere: the output build is the agent's implementation, not the engine's (runtime + tests + contracts)

## Scope

Make `build_output_as` the re-implementable seam for **every** agent (atomic and
composite), and remove the composite's "union of its branches" output — the
coupling the maintainer flagged across the Session 38 design discussion
("`output_as` es propiedad de un agente y nada más"; "no hay manera que pases
por separado algo a un método … tienes que agrupar los output_as de cada branch
antes de ejecutar el método build, pero garantizando que no haya colisión en los
slots"; "el modelo básico por defecto [del composite] no vale, porque no validará
necesariamente contra el `output_schema`"; "no es solo el composite, es cualquier
agente incluido los atómicos"). Per rule 12, the steps were walked with the
maintainer one at a time before authoring.

## Work done

**Runtime (`src/legio/`).**
- `agents/base.py`: added `build_output_as(self, info)` — the seam every agent
  re-implements. It always receives its produced `info` as a parameter and
  returns `{output_as: value}` (construction, §12.1). Documented: the engine
  never guesses an output shape; basic models live per type as overridable
  defaults; a pattern may inherit and build its own model for any agent type.
- `agents/tool_agent.py`: `_handle` now hands the tool's `raw_output` to
  `build_output_as`; the **basic tool-output model** wraps it under `output_as`
  as-is (overridable by inheriting `ToolAgent`). Signature/schema failures stay
  on the never-silent error path (rule 9).
- `agents/linguistic_agent.py`: `_handle` hands the record's `model_dump()` to
  `build_output_as`; the **basic linguistic-output model** wraps it (already
  validated by lingo against the compiled `output_schema`; overridable).
- `agents/composite_agent.py`:
  - Fan-in on all-complete now **groups the branch results by their join slot**
    (`{branch_id: {output_as: value}}`) — the autogenerated uuid4 `branch_id` is
    the collision-free grouping key, so two leaves ending in agents with the
    **same** `output_as` occupy distinct slots and both survive (previously
    `_build_branch_payload` did `gathered.update(...)` — a flat union that
    collapsed same-key leaves and even collided two error results).
  - `_build_branch_payload` **removed**. The grouped mapping is handed to
    `build_output_as`, the pattern's seam. The engine composite has **no generic
    default build** (a default cannot validate against an arbitrary declared
    `output_schema`): a concrete composite inherits and implements it.
  - A composite's own build failure now surfaces **via its own continuation**
    (`{error: ...}` resumed through the composite's level and closer) instead of
    escaping into the child's routing context (which would mis-route and
    re-deposit onto the gathering queue, a silent busy loop). Added
    `composite build failure` WARNING event.
- `flow/payload.py`: `build_payload(output, *, output_as)` now accepts **any**
  produced value, not only mappings — dropping the `dict(output)` coercion that
  broke the plain-text default output model. `output_as: "the_text"` is a
  string, never a nested `{text: ...}` wrapper.

**Tests (`tests/`).**
- `test_leg040/041/043/044` and `test_leg032`: the standalone `CompositeAgent`
  instantiations became concrete fictitious-domain subclasses
  (`GatherComposite`) implementing `build_output_as` — proving the composition
  is the pattern's, not the engine's. All prior output shapes preserved.
- `test_leg041`: added `test_composite_slots_never_collide_on_shared_output_as`
  (two same-`output_as` leaves both visible, keyed by slot position — the exact
  union-collision the old code hit) and
  `test_composite_build_failure_surfaces_via_own_context` (a raising
  `build_output_as` yields a visible error on the composite's closer, gather
  queue not re-fed, no loop).

**Docs.**
- `CONTRACTS/LEG-040`: Build/Interface/Acceptance state the collision-free slot
  grouping + `build_output_as` seam, no engine default, no `emit` remap.
- `AGENT_LIFECYCLE.md` §12.4 fan-in (group by `branch_id` slot → pattern's
  `build_output_as`; no generic engine default) — §4.10.6 already said "the
  agent's implementation".
- `ARCHITECTURE.md` §5 (composite fans in, groups slots, builds via the
  pattern's `build_output_as`).

## Decisions taken

- `build_output_as(info)` is **the** output-building seam for any agent type: it
  receives its produced info as a parameter and returns `{output_as: value}`.
  `output_as` is a property of one agent and nothing else — there is no
  "output_as per branch/scope" and no loader uniqueness rule is imposed (the
  declared §4.10.8 static `output_as` uniqueness stays docs-level).
- The composite fan-in grouping key is the **join slot** (`branch_id`, uuid4):
  collision-free by construction; same-`output_as` leaves and multiple error
  results coexist per slot. Composition of those slots into `output_as` is the
  concrete pattern's implementation (must validate against its declared
  `output_schema`); the engine ships no generic composite default.
- Basic models (tool: raw output as-is; linguistic: record dump) are defaults
  only — a pattern may inherit and re-implement for any agent type.
- A composite's own build failure is not routed through a child's context: it is
  resumed through the composite's continuation as a visible `error` result
  (rule 9), join closed exactly once.
