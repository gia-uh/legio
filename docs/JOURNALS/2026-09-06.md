# 2026-09-06 — Session 65 — Pools config block in the node configuration schema

## Scope

Maintainer request: add the pools proposal (LEG-080 horizontal capacity) to the
node configuration schema. Design discussion settled the placement: pool size is
**deployment/operator capacity, not functional definition** — it lives in the
node config (`pools:`), never in the pattern YAML spec. The `patterns` block
already follows the Schema 1 per-type directories
(`tool` / `linguistic` / `composite`, one dir each, `loader.py:172`
`load_pattern_dirs(pattern_dirs: Mapping[str, Path])`).

## Work done (per issue)

- **`src/legio/config.py`** — added `PoolsConfig` and wired it into
  `LegioConfig.pools`:
  - `per_pattern: dict[str, int]` — specific pattern name (highest).
  - `per_kind: dict[AgentKind, int]` — by Schema 1 kind. Only the two real
    KINDS (`tool | linguistic`) are admitted; `type: composite` has **no kind**
    in Schema 1 (`schema1.py:26` `AgentKind`, `schema1.py:133` "composite must
    not have kind"), so composites resolve via `per_pattern` or `default`.
  - `default: int | None` — global (lowest); caller falls back to `1` when
    `None`.
  - `resolve(pattern_name, per_kind) -> int | None`: highest wins
    `per_pattern > per_kind > default`; `0` ⇒ class born disabled.
  - Validation: negative counts rejected (`ConfigError`, rule 9); `per_kind`
    keys are typed as `AgentKind` so an unknown kind key fails loudly at load.
  - Segmenting the blocks (`per_pattern` / `per_kind` / `default`) removes the
    name-collision risk of a flat `all` / `<kind>-all` scheme: pattern names live
    in their own namespace, reserved keys are only the two Schema 1 KINDS.
- **`tests/test_leg081_config.py`** — pools coverage:
  - Defaults empty; full config loads `per_pattern`/`per_kind`/`default`.
  - Resolution precedence: per_pattern wins; falls back by kind, then default;
    composite (per_kind=None) via per_pattern/default; `None` when nothing
    matches; `0` allowed.
  - Fail-fast: negative sizes and unknown kind keys → `ConfigError`.
- **Formatting**: `ruff format` applied to the two touched files (clean).

## Logging added

None new (config load already logs `INFO loading config file` and `ERROR

## Decisions taken

- Pool size is **node-config operator capacity** (`pools:`), resolved at class
  creation by the Runtime; the pattern YAML stays purely functional (rule 7).
- Resolution order: explicit `--pool N` (invocation) > `per_pattern` >
  `per_kind` > `default` > `1`.
- `per_kind` is restricted to the real Schema 1 KINDS (`tool | linguistic`);
  composite resolves by name or default.
- Pools are *intent*; the catalog records the *real* count of instances brought
  up (mirror rule) — the resolve helper returns the intent, callers apply it.
- Docs (LEG-080 DRAFT, AGENT_LIFECYCLE §4.3/§4.8/§8.1, journal = the config
  shape) still to be updated to the `pools:` block in a docs turn.

## Known issues / open points

- The Runtime's class-creation path does not yet consume `pools.resolve(...)`
  (routing into `create_class` is an R-8 slice); this config block is the
  schema only.
- CLI override `--pool N` is not yet represented in `CliOverrides` (it belongs
  to the class-create verb, not the node CLI flags, and will land with the
  Runtime slice).

## Work done (per issue)

- **`docs/CONTRACTS/LEG-083-manager-generic.md`** — DRAFT contract (rasante
  R-8, GitHub issue #47 provisional — `gh` unavailable, the maintainer holds the
  issue): task shape, beaver footprint, surface, task-executor algorithm,
  executor-death and multi-process semantics, logging, acceptance criteria from
  §6.1 verbatim.
- **`docs/PLAN.md`** (R-8) — LEG-083 entry added after LEG-082 (accept: any
  kind of task managed; footprint exactly `tasks`/`pending_tasks`/`control`;
  `<node_id>:<uuid>` task ids; task ≠ agent cycle).
- **`tests/test_leg083_manager.py`** — contract tests written **first (red**:
  `ImportError` on `legio.manager.Manager`), then implementation (green). 22
  tests: registration and node-id validation; task-id minting as
  `<node_id>:<uuid>` matching `validate_task_id`; TaskRecord field census and
  JSON round-trip (args/kwargs are record data, so JSON-serializable only);
  footprint is exactly the three manager scopes; lifecycle
  pending→running→success and →failed (callable raising) with result/error in
  the record; unknown task id → `None`; a single task runs **once** across two
  executors (destructive `get()`); crashed-executor task is surfaced visibly
  (stays visibly `running`) and **never re-run**; `cancelling` half-open state
  and `failed(cancelled)` are visible; pause is non-terminal suspension (stays
  `running`, resumable to success); cancel never invokes a not-started callable;
  cancel of a **parked generator** closes it (`finally` observed) and lands
  `failed(cancelled)`; pause/resume of a **parked generator** across run
  passes preserves the last-yielded value as the result; callables are the
  async fn and the async generator (cancellable) kinds.
- **`src/legio/manager/__init__.py`** — `TaskStatus` enum, `TaskRecord`
  (`name`, `args`, `kwargs`, `status`, `result`, `error`, `enqueued_at`,
  `started_at`, `finished_at`), module-level `Manager` class:
  - Beaver footprint exactly §6.1: dict `tasks`, queue `pending_tasks` (priority
    0), dict `control` (run|pause|cancel, TTL 60s, expiry = no control).
  - Surface: `register(name, callable)` (in-process), `submit_task(name, *args,
    **kwargs) -> task_id`, `status(task_id) -> TaskRecord | None`,
    `pause`/`resume` (non-terminal), `cancel` (terminal, cooperative), and
    `run()` — one non-blocking polling pass that returns the number of task ids
    dispatched (empty queue → `0`, no error). Constructor rejects a `None` db
    (`TypeError`, rule 9) and validates `node_id`.
  - Executor: `pending_tasks.get(block=False)` → `_dispatch` (`IndexError` ⇒
    nothing due). Plain callables: `await callable(*args, **kwargs)` once (a
    crashed task is failed visibly, **not re-run**). Async generators
    (cancellable kind): driven step by step in `_drive_parked`, inspecting
    `control` before each `yield` — `run` advances, `pause` parks the generator
    in-process (task stays `running`), `cancel` → `cancelling` (visible) →
    `aclose()` → `failed(cancelled)`. Generators carry the last-yielded value
    across parked segments (`_last_yields`) as the final `result`.
  - Dispatch gates: a task under `pause` or `cancel` control **before** the
    callable would start is never invoked (cancel-on-pending lands
    `cancelled` without a call; pause-on-pending stays `pending`, out of the
    queue, and `resume` re-enqueues it).
  - Logging with the implementation (rule 11): INFO on submit/running/success,
    WARNING on cancelled/park-considered-denial/re-dispatch-of-a-running-task,
    ERROR on unregistered names, `logger.exception` on callable crashes.
  - `Manager` and the business `submit`/`status` coexist in the module; all
    names exported via `__all__`.

## Design decisions

- `args`/`kwargs` are part of the persisted record, so they must be
  JSON-serializable (beaver dict round-trips through JSON). Test gates use an
  **in-process** `asyncio.Event` and closure, never an `Event` passed as an arg
  (pydantic serialization rejected it — surfaced, rule 9).
- Parking is **in-process only** (§6.1: "pauses a task; cooperative"); the
  resume/cancel re-enqueue path requires the generator to be in `self._parked`
  (same process) or the record `pending`.
- `control` entries carry a TTL; absence/expiry ⇒ run (control is ephemeral
  intent, the record is the authority).
- The race-prone sleep-based mid-run tests were replaced by deterministic
  `asyncio.Event` gates so pause/cancel hit the parked generator reliably.

  DAG, or the Registry — the decoupling boundaries of §6.1 are kept (no
  instance_id, no domain names).
