# 2026-09-26 — Session 129 (turn 3): LEG-106 idle executor (with a shutdown-hang fix)

## Scope
Maintainer direction "continua": implement **LEG-106** (GitHub #55) — an idle
executor must not spin. Turn includes a mid-implementation root-cause fix of a
shutdown hang the first attempt introduced.

## Work done (per issue)

### LEG-106 / #55 — the idle executor does not spin (implemented, green)
- **`Manager.run()`** now returns the *dispatched* count: a plain callable /
  stillborn generator that produced a terminal fact → `1`; an empty pass **or**
  a pass that only skipped/parked an item (paused task, parked bring-up
  checkpoint) → `0`. New `Manager.last_dispatched` names the task of a non-zero
  pass. `_dispatch` returns a bool.
- **`Manager.wait_for_pending(timeout)`**: a **non-blocking** pop used as a
  wake-up hint. Chosen over `get(block=True, timeout=…)`.
- **`executor_loop`**: on an empty pass the pump parks on a bounded
  `asyncio.sleep(_EXECUTOR_IDLE_WAIT)` instead of `asyncio.sleep(0)`; it loops
  at once when work was dispatched. It never uses `get(block=True)`.
- **Root cause found (beaver)**: `AsyncBeaverQueue.get(block=True, timeout)` is
  a **0.1 s polling loop** (`await asyncio.sleep(0.1)` each spin), *not* a true
  suspension. Parking on it would spin at 10 Hz AND, with `timeout <= 0.1`,
  can overshoot forever (the timeout check runs after the sleep). That is what
  hung the suite mid-implementation (`test_status_returns_failed_not_raises`
  passed alone, hung in combination). The fix: park on `asyncio.sleep`, not on
  the queue.
- **`_shutdown_pumps`**: the join of a cancelled pump is now bounded
  (`asyncio.wait_for`), so a wedged queue await can never hang shutdown; a
  timeout is a visible WARNING. `_EXECUTOR_IDLE_WAIT = 0.05`,
  `_SHUTDOWN_SETTLE = 0.7` (park well under the settle so a parked pump sees
  `stop` on its own).
- **Tests**: `tests/test_leg106_idle_executor.py` (2) — a counting manager
  proves an idle pump makes < 50 passes over a 0.5 s window (was ~1245 with
  `sleep(0)`, verified red) and that the pump returns promptly on `stop`.
  `test_leg083` pause/resume passes updated to the new dispatched-count
  contract (a paused skip and a parked checkpoint report `0`).

## Logging added (rule 11)
- `legio.cli`: `cli executor shutdown pump_unjoined (queue await wedged)`
  WARNING when a cancelled pump cannot be joined within the grace.

## Tests run
- Red: `test_leg106` counted 1245 empty passes under the old `sleep(0)` loop.
- Green: full suite `-v --tb=line` → **661 passed** (659 + 2 LEG-106);
  `ruff check` clean; `ruff format --check` clean; `pyright` 0/0/0.

## Decisions taken
- **Do not park on beaver `get(block=True)`**: it is polling, not a suspension
  (contradicts the session-37 phrasing). The idle back-off is a bounded
  `asyncio.sleep` — rule 8 holds (idle back-off, not scheduling).
- **`Manager.run()` stays `int`** (dispatched count) with `last_dispatched` for
  the id, rather than returning `list[str]`: keeps ~25 call sites/tests
  untouched while still giving the host the work/no-work signal.
- A resumed parked generator / a paused skip reports `0` (no terminal work):
  the host parks rather than spins on it.

### #59 — a restarted node serves again (implemented, green)
- **Root cause (confirmed)**: the catalog **registry persists** in beaver while
  an agent's instance — its standing loop — is **process-bound** (LEG-087/095).
  After a restart `create_from_catalog` → `create_class` saw the class still
  recorded and did a **no-op**, so **no instance was brought up**: no consumer
  on the class queue, and every submit stayed `running`. (A second symptom seen
  while reproducing: two servers over the same db → beaver's internal lock
  `TimeoutError: Cannot acquire lock` — a separate misuse, not this bug.)
- **Fix** (`Runtime.create_class`): a recorded class is a no-op **only if it has
  a live instance** (a bring-up task in `_instance_tasks`, which is in-process
  and not persisted). A recorded class with **no live instance** (the restart
  case) is **revived**: its pool is brought up again, born enabled per its
  dependencies, gate set. The docstring documents the rule.
- **Red-first test** `tests/test_issue59_restart.py`: boot → stop → boot on the
  SAME db → the second round-trip completes. Red before the fix (`running`),
  green after. The dev-server reproduction (`run1 completed` / `run2 running`)
  matched exactly.
- **CHANGELOG**: `[0.1.1]` gained the #59 Fixed entry (still unreleased tip).
